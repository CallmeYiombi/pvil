# P0 작업 지시서: G0 미달 원인 진단

> 작성 2026-10-16. P0 작업 8(G0 판정 → 미달 시 진단)의 세부 계획. 상위 문서 `P0_reproduction.md` §7-8.

## 1. 설명해야 할 현상

| 데이터셋 | view | R@10 원문 | R@10 우리 | Δ |
| --- | --- | --- | --- | --- |
| RxRx1 | C | 0.742 | 0.858 | +0.116 |
| RxRx1 | S | 0.322 | 0.571 | +0.249 |
| RxRx3-core | C | 0.296 | 0.458 | +0.162 |
| RxRx3-core | S | 0.123 | 0.361 | +0.238 |

- 4개 run 모두 recall이 원문보다 **높다**(보통의 재현 실패와 반대 방향).
- S/C 비율(R@10): 원문 0.43(RxRx1)·0.42(RxRx3-core), 우리 0.67·0.79. 마스킹으로 맥락을 지워도 우리 모델은 덜 잃는다.
- RxRx1은 well 수가 원문과 거의 같다(12,229 vs 12,581) → 갤러리 크기는 주원인 후보에서 낮춘다.
- ESM2를 쓴 RxRx3-core도 격차가 있다 → "RxRx1 학습 가능 siRNA 표" 가설은 낮춘다.
- replicate mAP는 정의 문제로 따로 다룬다(`progress.md` 이슈 0, `scripts/diagnose_map_defs.py`).

## 2. 가설과 검증 (비용 낮은 순)

### 1단계: 재학습 없음 (기존 `best.pt`·임베딩 재사용, 추론·CPU만)

| # | 가설 | 검증 | 판정 |
| --- | --- | --- | --- |
| D1 | 평가 임베딩 층 차이. 우리는 projection head 128차원을 쓴다(decisions 2026-10-14, [원문 없음]) | 같은 `best.pt`로 백본 CLS 768차원 임베딩 → 같은 후처리 → recall | CLS에서 R@10·S/C 비율이 원문 쪽으로 크게 이동하면 유력 |
| D2 | 원문 모델은 학습이 덜 됐다 | 학습 없는 DINOv3 CLS(LoRA·어댑터 초기값)로 C/S 평가 | frozen ≈ 원문이면 D5로 |
| D3 | 지표 오염(shortcut) | G1 well당 세포 수, G2 well 위치, G3 FOV 강도 통계로 cross-batch R@10 (계획서상 E0 필수, 미실행) | G 값이 높으면 S/C 비율 해석의 근거. RxRx1은 siRNA 위치가 experiment마다 무작위라 G2는 낮을 것으로 예상 |
| D4 | 후처리 단계별 기여 | raw well 평균 / sphering만 / PCA만 / 전체 각각에서 recall | 어느 단계에서 크게 오르는지 |

### 3단계: 코드 대조 (1·2단계에서 원인이 안 나올 때)

- P0 §7-8의 (a)–(d) 순서: 증강·샘플러 층화 → 채널 순서·정규화 → sphering fit 대상·Harmony batch key → 갤러리 구성
- RxRx3-core 원문 104,166 wells vs 우리 81,314 wells: 원문이 다른 well 유형을 갤러리 방해 항목으로 넣었을 가능성

## 3. 규칙

- held-out 배치 지표를 여러 번 계산한다. E0 P-orig 예외(P0 작업 8)로 보고, 실행할 때마다 `docs/decisions.md`에 날짜와 run을 남긴다.
- 진단 결과를 P-strict 설정이나 하이퍼파라미터 선택에 쓰지 않는다.
- 원문에 맞추려고 우리 고정 설정(평가 층, epoch 정의 등)을 바꾸는 것은 사전 등록 변경이므로 사용자 승인과 decisions.md 기록이 필요하다.
- 진단 결과 저장: `results/E0_diag/<진단>/<method>/<dataset>/seed0/`. 고정 결과 `results/E0/`는 덮어쓰지 않는다.

## 4. 순서

**2026-10-16 범위 축소 (경로 A, decisions.md):** G0가 정성 기준(Q1–Q7)으로 바뀌고 파이프라인을 고정했으므로 원문 수치 추적은 하지 않는다.

- 실행: D3(G1–G3, E0 필수 항목), D4(후처리 단계별, CPU만)
- 사용자 결정 대기: D1·D2(CLS·frozen 임베딩, 약 3–4 GPU-시간, 부록 설명용)
- 하지 않음: D5(짧은 재학습), 3단계(코드 대조). 정성 현상 Q1–Q6이 미달할 때만 다시 검토
